# v0.16.2 - Forward output alignment

**Release date:** 2026-10-12
**Tag:** `v0.16.2`

## Objective

v0.16.2 aligns the default Vulkan and Metal Forward lighting/output profile
and stabilizes directional selection and Hydra camera-light energy. Focused
native and host fixtures preserve image, AOV, replay and resource contracts.
Broader Forward quality remains a separate roadmap item.

## Completed capabilities

- Vulkan and Metal select the smallest stable directional-light handle rather
  than a dense table slot. Shared normalization retains world-space direction
  through compaction, translation and camera motion, recovers degenerate axes
  to +Z, preserves zero energy and rejects invalid selected color/intensity.
- Hydra converts distant-light radiance using angle, normalize, exposure and
  diffuse into a face-on Lambert response. Hdx's camera light becomes roughly
  0.321 instead of a shading multiplier of 15000. Invalid edits retain the
  previous light atomically with structured diagnostics.
- Both default shaders use 0.15 packaged Lambert SH environment fill plus
  0.85 directional Lambert lighting and component-wise Reinhard compression
  before the linear RGBA8 color AOV. Metal white Camera Light OFF retains
  headroom in native, Tier 0 and HgiMetal linear/sRGB output.
- `Merlin::RenderBackend` exposes the GPU-independent Radiance loader and
  Lambert SH projection/evaluation, with embedded default coefficients checked
  against the packaged HDR. Vulkan retains configurable HDR environments.
- Independent native/host lighting, first-frame camera sweeps, Qt navigation
  and optional external multi-mesh USD fixtures retain exact settled/replay,
  restored AOV/image and zero steady geometry upload/pipeline creation gates.
  The offline comparator checks profile-tagged independent backend centers.
- Hosted Hydra compilation CI covers pinned OpenUSD 26.05/26.08 CPU contracts,
  shader ABI, installed consumption and plugin discovery separately from GPU
  runtime evidence. SDK provisioning includes VMA and an opt-in Vulkan loader;
  Python SDK relocation and CMake 3.x manifest policies are corrected. Vulkan
  capability CI provisions the checksum-pinned official testusdview launcher
  and requires executed native/host/AOV/install coverage without missing tests
  or skips. Device host validation uses the pinned OpenUSD 26.08 Vulkan
  Lookdev artifact with Python 3.13.14 explicitly selected; SDK-only
  26.05/26.08 checks retain their separate role.
- Hydra indexed primvars now recognize OpenUSD's `primvars/name:indices`
  dirty locators. Authored face-varying inputs follow handedness edits; an
  indices-only normal edit/restoration preserves exact image recovery without
  point/topology refetch or triangulation.
- Metal Mesh/Gaussian composition tests independently capture opaque Mesh
  output and Gaussian alpha, preserving their composite, occlusion, depth,
  picking and CPU/GPU differential checks under the new compressed output.

## Compatibility and limitations

- Consumers should rebuild after the RenderBackend environment API/library
  relocation. Metal's internal host/MSL material block grows from 48 to
  192 bytes with size/offset assertions; public Metal options remain unchanged.
- Metal reference images intentionally change with the shared SH/Reinhard
  profile. Hydra authored distant-light images also change with energy
  conversion; native Core intensity remains a directly specified Lambert
  response. Camera Light OFF selects the existing unit-white +Z fallback
  when no directional source remains; it is not ambient-only rendering.
- Default center comparisons do not establish full-image backend rasterization
  parity or custom Vulkan HDR parity. Multiple-light accumulation, shadows,
  selectable exposure/tone mapping, generated Metal material ingestion,
  unrestricted navigation and broader Kitchen/interior quality remain open.
- Metal execution evidence is specific to Apple M3/OpenUSD 26.08. Other GPUs,
  SDKs and controlled timing require independent evidence. Host tests use
  Metal API validation; native/AOV tests additionally retain shader validation
  because host instrumentation fails OpenUSD display pipeline creation.
- SDK assets remain Windows/Linux Core and macOS Apple Silicon Core + Metal.
  Vulkan, Hydra and MaterialX runtime products remain source-build products.
