# v0.16.0 - GPU-driven Mesh and Gaussian rendering

**Release date:** 2026-09-30
**Tag:** `v0.16.0`

## Objective

v0.16.0 ships opt-in Vulkan GPU-driven indexed Mesh submission and Vulkan/Metal
Gaussian GPU preparation, sorting and image-producing rasterization. The
validated scope is explicit: conventional Forward and CPU-sorted Gaussian
rendering remain the default correctness references and capability fallbacks.
Remaining quality and hardware coverage work continues after this release.

## Completed capabilities

- Vulkan indexed-indirect Mesh submission uses persistent GPU Scene candidates,
  visibility/frustum culling, compaction and arena/pipeline batches. Warmed
  static and camera frames avoid CPU preparation draw visits, scene uploads,
  allocations and descriptor writes in the supported fixtures.
- Vulkan and Metal Gaussian execution consumes persistent source attributes,
  performs projection/covariance/SH evaluation, frame-wide radix sorting,
  gather and indirect sorted-stream rasterization. GPU camera frames avoid CPU
  particle preparation and prepared-stream uploads; localized edits retain
  partial source uploads and completion-safe resource/scratch lifetimes.
- Both backends support opt-in pair binning, sorting and compute tile raster.
  Pair overflow keeps the complete sorted-stream draw on the GPU. Disabled,
  preferred and required policies report actual selection, rejection and
  fallback through renderer settings, Hydra flags and viewport controls.
- Device stage timestamps, four-AOV image comparisons and per-sample counters
  separate preparation, sort, tile, raster, readback and host presentation.
  Same-runtime Tier 0/HgiVulkan and HgiMetal GPU-copy comparisons retain image
  evidence; color GPU copy leaves depth and IDs on CPU readback.
- Vulkan host-cached AOV readback, generated-material preparation/descriptor
  caches, Hydra left-handed Mesh triangulation, shared transformed Gaussian SH
  evaluation and Metal Mesh constant/sampler fixes improve existing paths.
- Windows/Linux Core SDK and macOS Apple Silicon Core + Metal SDK packaging
  retain metadata and SHA-256 sidecars. Metal now packages build-time compiled
  Gaussian shaders; release automation installs the checksum-pinned Slang
  compiler used by Metal CI.

## Compatibility

- GPU execution is opt-in. Renderer settings v2 carries Mesh submission policy;
  v3 adds Gaussian execution policy. Consumers must rebuild against the updated
  headers and libraries; binary compatibility with v0.15.0 is not promised.
- GPU-driven Mesh submission is Vulkan-only for supported basic/textured
  materials. Metal Mesh and generated Vulkan materials retain conventional
  submission, with explicit required rejection and preferred fallback.
- Gaussian sorted-stream and tiled modes are available on Vulkan and the
  validated Apple M3 Metal configuration. Core-only builds retain no GPU SDK,
  Slang or Metal compiler dependency. Vulkan, Hydra and MaterialX
  runtime products remain source-build products.

## Known limitations

- Vulkan 10M tiled output exceeds the six-unit RGBA8 color bound (8 static,
  10 moving). Its benchmark returns failure; sorted-stream passes at 1M/5M/10M,
  while tiled passes at 1M/5M. The failing 10M result is not acceptance evidence.
- Apple M3 offscreen tiled checks cover 65K/1M with at most 2/255 color error
  and exact depth/IDs. The 8,192-particle HgiMetal tiled host capture passes its
  aggregate image policy but has a sparse 15/255 color tail. Larger tiled host
  captures, native viewport tile captures and other Apple GPUs remain unverified.
- Tiling can cost more overall than sorted-stream because binning/sort outweigh
  raster savings. Local timing uses unpinned clocks/power and is not a universal
  speed guarantee. GPU stage medians are not additive frame estimates.
- One pre-existing macOS Mesh usdview movement assertion remains a host test
  gap, reproduced on the unmodified earlier commit. Passing Gaussian evidence
  does not resolve that Mesh test.
- Generated material command recording remains linear in draw count; generated
  bindless execution, Metal GPU-driven Mesh, Gaussian LOD/compression/streaming,
  and broader Linux Vulkan runtime coverage remain outside the release scope.
