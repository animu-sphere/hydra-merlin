# v0.11.0 - Native Metal offscreen backend and residency

**Release date:** 2026-07-27
**Tag:** `v0.11.0`

## Objective

v0.11.0 adds a production native Metal backend for offscreen Mesh Forward
execution on Apple platforms. It consumes the same host-neutral scene,
submission, completion, render-product, diagnostic, and telemetry contracts as
Vulkan while keeping Metal device, resource, shader, synchronization, and
readback ownership inside `Merlin::Metal`.

## Completed capabilities

- Optional `Merlin::Metal` package and installed CMake component with native
  device and command-queue setup, runtime-compiled renderer-owned MSL, Forward
  color and depth pipelines, and explicit submit/completion/resolve behavior.
- Host-neutral Mesh, instance, camera, texture, sampler, basic material, and
  opacity-mask inputs with offscreen color, depth, `primId`, and `instanceId`
  products and selectable CPU readback.
- Heap-backed scene residency, revision-aware buffer and texture reuse,
  completion-protected retirement, and frames-in-flight target/readback reuse.
- Finite generation-checked texture and sampler slots with actionable
  exhaustion diagnostics and stale-handle rejection.
- Metal argument-buffer tier negotiation. Tier 2 uses per-frame, dirty-only
  texture/sampler table encoding; unsupported devices retain conventional
  Forward bindings.
- Backend-neutral and Metal-specific capability, capacity, residency,
  allocation, retirement, table-update, and fallback telemetry.
- Automatic backend selection can choose Metal on supported Apple platforms
  without changing Core-only or Vulkan dependency boundaries.
- Isolated install-consumer validation for the exported `Merlin::Metal`
  component and release metadata describing the optional backend and target.

## Compatibility

- Core public APIs remain independent of Metal, Vulkan, OpenUSD, Hydra, GLFW,
  Qt, and DCC SDK types. Metal native handles and synchronization primitives do
  not cross the backend-neutral contract.
- `MERLIN_ENABLE_METAL=OFF` retains existing Core, Vulkan, MaterialX, adapter,
  and installed-package behavior. Metal is optional and disabled by default.
- The backend requires macOS, the system Metal framework, and a Metal-capable
  device. Argument-buffer tier 2 is negotiated at runtime rather than assumed.
- Conventional Forward is the correctness fallback when tier-2
  argument-buffer tables are unavailable.
- Vulkan 1.4 and OpenUSD 26.05 remain the existing Vulkan and Hydra boundaries;
  this release does not change them.

## Known limitations

- v0.11.0 is an offscreen backend release. Native `CAMetalLayer` viewport
  presentation remains v0.12.0 work.
- Hydra host presentation through HgiMetal remains v0.13.0 work. Hydra continues
  to have the universal Tier 0 CPU RenderBuffer path.
- The Metal backend implements the basic Mesh Forward material slice; generated
  MaterialX execution on Metal, Gaussian rendering, GPU-driven submission,
  Visibility, meshlets, Mesh Shader, Hi-Z, and LOD remain later work.
- CPU readback is explicit and selectable, but the fixed pass may still write
  attachments that were not requested for transfer.
- Hosted macOS jobs provide build, test, install-consumer, and package evidence.
  GPU runtime image and residency behavior is backed by local Apple Silicon
  capability evidence rather than a dedicated continuously available GPU
  runner.
