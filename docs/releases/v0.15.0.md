# v0.15.0 - Persistent GPU Scene and Gaussian residency

**Release date:** 2026-08-11
**Tag:** `v0.15.0`

## Objective

v0.15.0 establishes a versioned, persistent GPU Scene boundary for Forward
rendering and completes persistent Vulkan residency for Hydra Gaussian splat
source attributes. The release preserves correctness fallbacks while ensuring
unchanged scenes require no scene-table or Gaussian-attribute transfer work.

## Completed capabilities

- Common ABI-v1 packing for geometry, instance, material, and draw records,
  with stable 64-bit draw identity, generation checks, transactional upserts,
  explicit 32-bit representability validation, and coalesced dirty-copy ranges.
- Completion-safe persistent GPU Scene residency for geometry, instance,
  material, and draw tables. Exact deltas retain unchanged physical slots;
  resource-record movement refreshes dependent draws so they cannot reference
  retired generations.
- Optional Vulkan device-local ABI-v1 tables with a persistently mapped upload
  ring, exact range and capacity validation, contiguous dirty-range copies,
  asynchronous-transfer synchronization, and allocation/copy telemetry.
- Vulkan bindless Forward consumption of the resident GPU Scene tables. The
  dense draw-to-physical-slot mapping and frame view state are the remaining
  CPU dispatch inputs; transforms, IDs, material factors, and bindless resource
  indices resolve from the tables.
- Optional Metal private ABI-v1 tables with completion-safe shared staging,
  one blit per contiguous dirty range, equivalent revision validation, and
  renderer consumption with the conventional Forward fallback retained.
- Generation-checked persistent Gaussian identity and Vulkan device-local
  position, covariance, opacity, and spherical-harmonic source ranges. Static
  snapshots allocate and upload nothing, particle edits transfer only the
  changed source aspect and range, and transform or visibility revisions do
  not re-upload attributes.
- Separate CPU preparation, raw-attribute sync, prepared-stream sync, and GPU
  raster timing, plus opt-in deterministic 1M, 5M, and 10M Gaussian fixtures.
- Development viewport diagnostics for camera state, renderer settings,
  saved benchmark baselines, hitch thresholds, rolling timing history, and
  selected Color, Depth, Prim ID, or Instance ID inspection.

## Compatibility

- ABI-v1 GPU Scene table consumption is selected on Vulkan devices that pass
  the bindless feature and limit contract. Conventional Forward remains the
  fallback for generated materials and non-bindless devices.
- Metal accepts and consumes the common GPU Scene ABI through its private
  tables. Persistent Gaussian source-attribute residency is currently a Vulkan
  renderer capability.
- Gaussian splats continue to use Hydra's standard `particleField` Rprim and
  retain the v0.14.1 CPU preparation and deterministic sorting boundary.

## Known limitations

- GPU-driven Gaussian projection, sorting, tiling, level of detail,
  compression, and streaming are not implemented; these remain post-v0.15.0
  work.
- Mesh CPU submission is still indexed and draw-count dependent. GPU-driven
  indexed Mesh submission remains planned for v0.16.0.
- The advanced GPU Scene paths are optional. Devices that do not satisfy their
  capability contracts use the established conventional rendering paths.

## Verification evidence

- Core, Vulkan, and Metal tests cover ABI packing, stale-plan rejection,
  transactional recovery, completion-safe retirement, dirty-range accounting,
  capacity failures, and zero-work static snapshots.
- Vulkan runtime coverage verifies table-backed Forward output and packed
  object/instance IDs on both the initial upload and a subsequent zero-upload
  static frame. Metal coverage verifies table-backed draw consumption whenever
  a Metal device is available.
- Gaussian tests cover localized opacity and spherical-harmonic updates,
  zero static allocation/upload, deterministic IDs, completion-safe range
  retirement, and separated timing/fixture evidence.
