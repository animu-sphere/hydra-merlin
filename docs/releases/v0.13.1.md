# v0.13.1 - HgiVulkan direct-path hardening

**Release date:** 2026-08-01
**Tag:** `v0.13.1`

## Objective

v0.13.1 makes direct HgiVulkan resource sharing an affirmative, observable
capability decision. It evaluates the complete ownership, compatibility, and
lifetime contract without weakening the v0.13.0 GPU-copy path or treating
private HgiVulkan implementation details as public resource-import APIs.

## Completed capabilities

- One direct-share gate covering physical/logical device identity, queue
  ownership, API/extensions, format/usage, sample count, tiling, memory
  constraints, public texture import and host consumption, completion
  retention, resize retirement, and implementation availability.
- Stable per-gate rejection names and evaluation telemetry kept separate from
  the selected transfer fallback.
- Explicit Vulkan AOV usage, optimal tiling, device-local memory, exclusive
  sharing, queue-family, format, layout, stage/access, sample-count, and
  renderer-completion metadata.
- Sampled-image usage on the color AOV as a direct-consumption prerequisite,
  with the expanded source contract also validated by GPU copy.
- A maintained decision for OpenUSD 26.05/26.08: public Hgi cannot import a
  Merlin-owned `VkImage`, so both packages report
  `public-texture-import-unavailable` and retain GPU copy.

## Compatibility

- HgiVulkan GPU copy remains selected on the validated OpenUSD 26.05 and 26.08
  packages; color avoids CPU Map/upload while depth and ID AOVs retain CPU
  readback.
- Tier 0 CPU RenderBuffers remain the universal reference and fallback.
- Core and backend-neutral APIs remain independent of OpenUSD, Hydra, Hgi, and
  Vulkan native types. Direct-share policy remains inside the Hydra adapter,
  while Vulkan export metadata remains in the optional Vulkan backend API.
- Existing headless, native viewport, Metal, MaterialX, packaging, and
  install-tree behavior remains independently available.

## Known limitations

- Direct shared-resource presentation is not enabled. OpenUSD 26.05/26.08
  expose Hgi-owned texture creation and Hgi texture views, but no public import
  path or host-consumption completion contract for a renderer-owned `VkImage`.
- External memory and semaphore interop is not added: GPU copy is available,
  and cross-device handle transport would not repair the missing public host
  ownership and consumption boundary.
- HgiMetal host presentation remains v0.14.0 work.
