# v0.12.0 - Native Metal viewport presentation

**Release date:** 2026-07-27
**Tag:** `v0.12.0`

## Objective

v0.12.0 completes native Metal presentation for the development viewport on
Apple platforms. The adapter owns the Cocoa/GLFW window boundary while
`Merlin::Metal` owns drawable acquisition, GPU presentation encoding, completion,
pacing, and native resources. The same renderer output remains available for
headless and Hydra-host presentation paths.

## Completed capabilities

- Adapter-owned `CAMetalLayer` creation with renderer-owned drawable setup,
  pixel format, color space, and drawable lifetime.
- Renderer-owned fullscreen GPU presentation from the reference RGBA target to
  BGRA sRGB drawables, including linear sRGB to Display P3 conversion.
- Vsync and drawable-count pacing, resize-safe drawable extents, and
  frames-in-flight drawable retention with completion-safe reuse.
- Zero-readback normal viewport frames while preserving explicit color, depth,
  `primId`, and `instanceId` products for readback and diagnostics.
- Dear ImGui Metal rendering in the shared development viewport UI, retaining
  the existing camera, input, AOV, screenshot, benchmark, picking, and
  diagnostic behavior.
- Metal-only viewport builds and packaging, explicit Vulkan selection, and
  automatic Metal selection on supported Apple platforms.
- Presentation timing/copy telemetry and an explicit unsupported boundary for
  future HDR output; SDR sRGB is the default policy and Display P3 is supported.

## Compatibility

- Core public APIs remain independent of Cocoa, GLFW, Metal, Vulkan, OpenUSD,
  Hydra, Qt, and DCC SDK types. Native window and drawable handles remain
  inside the adapter and Metal backend.
- `MERLIN_ENABLE_METAL=OFF` retains existing Core, Vulkan, MaterialX, Hydra,
  adapter, and installed-package behavior. Metal remains optional and disabled
  by default outside Apple platforms.
- Explicit `--backend vulkan` continues to use the existing GLFW surface path;
  automatic selection prefers native Metal on supported Apple platforms.
- HDR output is not claimed. Unsupported HDR requests are rejected explicitly
  rather than inferred from a pixel format.
- Hydra host presentation through HgiMetal remains v0.13.0 work; Hydra retains
  the universal Tier 0 CPU RenderBuffer path.

## Known limitations

- The Metal path implements the basic Mesh Forward material slice. Generated
  MaterialX execution on Metal, Gaussian rendering, GPU-driven submission,
  Visibility, meshlets, Mesh Shader, Hi-Z, and LOD remain later work.
- The HgiMetal bridge is not part of this release; native viewport presentation
  and Hydra-host presentation remain separate ownership paths.
- Hosted macOS jobs provide compile, package, and install-consumer evidence.
  Apple GPU presentation behavior is additionally covered by local capability
  evidence rather than a continuously available GPU runner.

## Verification evidence

- Apple GPU tests cover hidden compositor-backed presentation, resize,
  zero-readback frames, validation, exact presented/offscreen reference parity,
  presentation-target validation, Display P3 configuration, and explicit HDR
  rejection in Debug and Release suites.
- Hosted macOS coverage builds and packages the Metal-only viewport, while
  combined configurations retain explicit Vulkan selection and automatic Apple
  Metal preference.
- Release preparation finalized `VERSION`, `openstrata.toml`, and the dated
  stable Changelog section for v0.12.0 on 2026-07-27.
