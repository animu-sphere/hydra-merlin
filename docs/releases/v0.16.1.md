# v0.16.1 - Gaussian quality and host validation

**Release date:** 2026-10-05
**Tag:** `v0.16.1`

## Objective

v0.16.1 closes the validated v0.16.x Gaussian quality and host-presentation
follow-ups, and adds Linux Vulkan software-driver coverage. GPU execution
remains opt-in; conventional Forward, CPU-sorted Gaussian rendering and
Tier 0 host presentation retain their reference and fallback roles.

## Completed capabilities

- Vulkan and Metal Gaussian CPU/GPU sorted streams and tiles accumulate in
  RGBA32F, convert once to the public RGBA8 AOV, and evaluate ellipse coverage
  at pixel centers. Independent low-opacity fixtures anchor the corrected
  reference. RTX A5000 1M/5M/10M static/motion captures pass the unchanged
  six-step tiled color bound, closing the historical Vulkan 10M failure.
- Apple M3 HgiMetal tiled captures reduce the public 8,192-particle color tail
  from 15 to 6/255; properly framed 1M host images match exactly. Native
  viewport captures at both sizes differ by at most 1/255. Offscreen color
  bounds and exact depth/ID requirements remain unchanged.
- HgiVulkan and HgiMetal copy color, depth and both ID AOVs into retained host
  targets. Depth composition stays on the GPU; non-color RenderBuffer Map
  downloads and caches only the requested current target. Normal unselected
  host frames avoid image readback, with bridge downloads reported separately.
- Metal Mesh winding follows host projection reflection, fixing the earlier
  usdview movement gap. Projection correction also works with native copy
  disabled, restoring Tier 0 orientation and click picking. Diagnostic depth
  readback preserves native depth composition and visible axis overlays.
- Qt click regressions cover selection, background deselection, movement,
  odd-sized resize, highlighting and axes. Apple M3/OpenUSD 26.08 Tier 0 and
  HgiMetal match exactly across all 21 compared Mesh phases.
- Linux Vulkan CI builds Debug/Release, validates production SPIR-V and
  executes Mesa lavapipe headless, Gaussian, lifetime/update, Xvfb/X11 viewport
  and installed SDK tests. GPU-free PR/release checks keep source, shader/ABI
  and package linking separate from installed GPU execution.
- Vulkan staging reuse is explicitly ordered. Unified-memory exhaustion
  tests retain their denial contract, Vulkan/Metal GLFW adapters no longer
  require unused OpenGL headers, and Linux SDK metadata records the version
  rather than the architecture directory.

## Compatibility and limitations

- Consumers must rebuild against the updated headers and libraries because
  renderer and Hydra telemetry layouts changed. Binary compatibility with
  v0.16.0 is not promised.
- Gaussian reference images intentionally change to remove accumulated
  per-splat RGBA8 quantization error. The retained RGBA32F working target costs
  16 bytes/pixel per frame context before allocation alignment; Gaussian raster
  timestamps include final conversion.
- Vulkan sorted streams retain the legacy format fallback where float
  blend/blit is unavailable. Tiled execution additionally requires float
  storage support and preserves required rejection/preferred fallback.
- Metal runtime evidence remains specific to the validated Apple M3.
  Other GPUs, controlled hardware timing, Linux real-GPU/native Wayland/Hydra
  execution and the added HgiVulkan Qt click regressions remain separate work.
  Local timing observations do not establish universal performance gates.
- SDK assets remain Windows/Linux Core and macOS Apple Silicon Core + Metal.
  Vulkan, Hydra and MaterialX runtime products remain source-build products.
