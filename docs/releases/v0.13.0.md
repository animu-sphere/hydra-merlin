# v0.13.0 - HgiVulkan GPU-copy host presentation

**Release date:** 2026-08-01
**Tag:** `v0.13.0`

## Objective

v0.13.0 starts low-copy Hydra host presentation with an HgiVulkan bridge. The
Hydra adapter owns Hgi targets and presentation policy, the Vulkan backend owns
renderer images and execution, and Tier 0 CPU RenderBuffers remain the universal
reference and fallback.

## Completed capabilities

- Public Hydra render-driver discovery and Hgi-owned color targets on the
  validated OpenUSD 26.05 and 26.08 runtime packages.
- A borrowed Vulkan 1.3 device and graphics-queue path for compatible HgiVulkan
  hosts, preserving the Vulkan 1.4 requirement for Merlin-owned contexts.
- Selected color-image export and same-queue `vkCmdCopyImage` with explicit
  layouts, stages/access, queue families, format, extent, and completion state.
- Move-only exported-image leases that retain renderer frame targets through
  Resolve and return only from Hgi command-buffer completion.
- Structured capability, rejection, target, byte, copy-time, completion, and
  coarse-wait telemetry. Missing, disabled, non-Vulkan, driver-swap, and
  operational rejection cases retain Tier 0 with actionable fallback reasons.
- A versioned 13-phase Tier 0/HgiVulkan image and performance comparison across
  scene edits, camera, material, diagnostics, removal/re-add, and resize.

## Compatibility

- Core public APIs remain independent of OpenUSD, Hydra, Hgi, Vulkan, Metal,
  Qt, and DCC SDK types. Host-native discovery and presentation remain inside
  the Hydra adapter.
- HgiVulkan GPU copy is selected only when the validated package exposes its
  native `hgiVulkan` target and the runtime capability checks pass.
- Tier 0 CPU RenderBuffer readback/upload remains available for every host and
  is the correctness reference. The selected GPU path copies color; depth,
  `primId`, and `instanceId` continue through CPU readback.
- Existing headless, native Vulkan viewport, native Metal viewport, Core-only,
  MaterialX, and installed-package behavior remains available independently.

## Known limitations

- Direct same-device resource sharing and external memory/semaphore interop are
  not claimed. They remain separately evidence-gated v0.13.1 work, with GPU
  copy as the fallback.
- HgiMetal host presentation remains v0.14.0 work.
- Generated MaterialX execution on Metal, Gaussian rendering, GPU-driven
  submission, Visibility, meshlets, Mesh Shader, Hi-Z, and LOD remain later
  milestones.

## Verification evidence

- OpenUSD 26.05 and 26.08 runtime smokes prove one GPU-copied color AOV, three
  CPU-readback AOVs, no color Map/host upload, non-zero host-consumption
  completion, safe resize, and zero coarse idle waits.
- Tier 0 and HgiVulkan run the same 13-phase regression. Raster-edge differences
  are bounded to 0.25% of pixels and a 0.25 mean channel error; the recorded
  OpenUSD 26.08 Windows evidence remained within both limits.
- That evidence records 1,289,520 fewer CPU-readback bytes per representative
  frame for GPU copy and separates readback, host upload, GPU copy, bridge
  completion, host composite, and presentation timing.
- Self-hosted capability CI retains the current renderer benchmark and current
  Tier 0/HgiVulkan path comparison rather than treating v0.7.0 as a permanent
  performance baseline.
- Release preparation finalized `VERSION`, `openstrata.toml`, and the dated
  stable Changelog section for v0.13.0 on 2026-08-01.
