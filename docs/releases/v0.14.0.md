# v0.14.0 - HgiMetal GPU-copy host presentation

**Release date:** 2026-08-02
**Tag:** `v0.14.0`

## Objective

v0.14.0 adds a public HgiMetal presentation bridge for Hydra hosts. It keeps
the native Metal renderer in control of its AOV resources while using Hgi-owned
targets and the host's Metal command queue for same-device GPU copy.

## Completed capabilities

- Hgi render-driver discovery and validated OpenUSD 26.05/26.08 HgiMetal
  selection with explicit disabled, missing-driver, non-Metal, unsupported,
  native-context, target, source, and copy fallback reasons.
- Hgi-owned color-target creation, target recreation and retirement telemetry,
  and Hgi command-buffer completion retention for Metal-local copies from
  leased renderer color AOVs.
- Tier 0 CPU RenderBuffer upload remains available when HgiMetal is disabled,
  unavailable, or an operational transfer step fails.
- An affirmative direct-share evaluator covering device identity, texture
  storage and usage, pixel format, command queue, completion retention,
  resize-safe retirement, public texture import, and implementation
  availability. Validated packages report the public-import rejection and use
  GPU copy.
- Hydra adapter bridge tests plus usdview smoke coverage, including the Metal
  heap capacity needed by the USD scene fixture.
- Forward-lighting hardening that preserves signed normal behavior and avoids
  an over-bright camera-light contribution in Hydra presentation.

## Compatibility

- The bridge is optional and only selected for HgiMetal on validated OpenUSD
  26.05 and 26.08 packages. Other driver/API combinations retain Tier 0.
- Color can avoid CPU readback/upload through the Metal-local copy path; depth,
  `primId`, and `instanceId` retain CPU RenderBuffer delivery.
- Core and backend-neutral interfaces remain independent of OpenUSD, Hydra,
  Hgi, and Metal-native types. Native HgiMetal types remain in the optional
  Hydra adapter and Metal backend boundaries.

## Known limitations

- Direct renderer-owned texture sharing is not enabled. OpenUSD public Hgi APIs
  do not provide the texture-import and host-consumption contract needed to
  adopt a Merlin-owned `MTLTexture`; GPU copy remains selected.
- HDR presentation remains outside this bridge. Its Hgi targets retain the
  existing SDR color-target policy.
- HgiVulkan retains its independent GPU-copy and direct-share capability
  boundary.

## Verification evidence

- Hydra adapter tests cover HgiMetal support selection, direct-share rejection,
  target validation, operational fallback, and target lifetime behavior.
- OpenUSD 26.05 and 26.08 usdview smoke coverage exercises the HgiMetal path
  and confirms the native Metal renderer can supply the scene fixture.
- Existing Vulkan behavior remains covered by the projection-orientation and
  renderer test suites after the Forward-lighting changes.
