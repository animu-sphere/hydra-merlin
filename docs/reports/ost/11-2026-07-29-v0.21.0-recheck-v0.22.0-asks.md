## Summary

OST 0.21.0 resolves the two asks that can be observed before a successful
renderer build. Managed configure progress now identifies the active child and
phase and reports elapsed time, time since output, log location, and a retained
CMake log tail. An explicit configure timeout removes the process tree and
releases the target lease; an immediate second invocation acquires the lease
normally. Generated preset includes are profile-local, so a USD renderer
workflow no longer depends on a separately generated core preset.

The underlying host configure still stops at `Detecting CXX compiler ABI info`.
Consequently neither `renderer view` nor `renderer viewport` reached executable
launch, and the successful launch JSON, durable viewport record, and
OST-owned producer binding remain undemonstrated rather than failed.

## v0.22.0 asks

1. Expose configure/build timeout controls on managed `renderer view` and
   `renderer viewport`, or document how those workflows inherit project build
   timeout policy, so renderer launch recovery can be exercised without waiting
   for the default configure timeout.
2. Add an upstream integration fixture that completes both renderer launch
   paths and asserts the persisted success/failure JSON envelope independently
   of a downstream renderer's compiler environment.
3. Add a negative managed-evidence fixture proving that a stale or separately
   produced renderer report cannot be promoted by copying or attaching a newer
   successful completion record.

Raw JSON, logs, runtime paths, and machine-specific process details remain
local and are intentionally not attached to this report.
