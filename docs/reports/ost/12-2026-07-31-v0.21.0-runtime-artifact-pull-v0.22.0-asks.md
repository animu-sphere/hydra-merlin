This pass replaces machine-local OpenUSD paths in Hydra GPU CI with the pinned
runtime artifacts published in the Animu-sphere GHCR package. The artifact and
OCI manifest pins both resolve correctly. In this run, each first uncached pull
reached OST's 120-second receive-response boundary while streaming its roughly
110 MB runtime archive. The observation reproduced for OpenUSD 26.05 and 26.08.
It may still reflect a transient runner, route, CDN, or registry slowdown rather
than a continuously reproducible service condition.

## Summary

- Both immutable OCI references resolve and identify the intended Windows USD
  runtime artifact.
- Both GitHub Actions jobs failed after approximately 122 seconds while streaming
  the archive layer, before import, materialization, configure, or GPU tests.
- The error is structured as `IO_ERROR`, but the CLI offers no timeout control,
  retry, resume, or reusable partial-download state.
- The Actions cache cannot bootstrap the first pull because it is saved only
  after a successful job.
- A diagnostic ORAS pull continued beyond 120 seconds, proving the package is
  accessible, but the connection later ended with HTTP/2 `PROTOCOL_ERROR`
  after 495 seconds and roughly 70 MB. A longer one-shot timeout alone is not a
  complete remedy; digest-safe retry and resume are required.
- A narrow `curl --continue-at -` control resumed that retained archive at byte
  73,400,320, downloaded the remaining bytes, and finished at 110,401,378
  bytes with SHA-256 `c69f...103ea`. This demonstrates that the same transient
  condition was recoverable without restarting the full layer.
- Importing an already complete 26.05 package directory with
  `ost artifact import` succeeds, verifies all 4,130 files, and produces the
  expected artifact digest. Package content and OST import are not implicated.
- A later fresh 26.08 control using the resumable downstream client completed
  all four OCI layers in 325 seconds without a retry, then imported and
  verified 4,297 files plus SBOM and provenance. This supports a transient
  transfer-speed explanation while also confirming that a valid uncached pull
  can legitimately exceed OST v0.21.0's observed boundary.

## Reproduction

The CI jobs use the same operation for each matrix entry:

```powershell
ost artifact pull $env:OST_RUNTIME_REMOTE `
  --expect-artifact $env:OST_RUNTIME_ARTIFACT `
  --require-kind runtime --json

ost runtime pull cy2026 --profile usd `
  --from-artifact $env:OST_RUNTIME_ARTIFACT --force
```

Observed GitHub Actions timing:

| Cell | Pull start (UTC) | Failure (UTC) | Result |
| --- | --- | --- | --- |
| OpenUSD 26.05 | 12:59:28 | 13:01:30 | `timeout: receive response` |
| OpenUSD 26.08 | 13:02:07 | 13:04:09 | `timeout: receive response` |

Both jobs use independently pinned artifacts, so identical timing across the
two cells is evidence that the configured client boundary was reached rather
than evidence that one package is malformed. It does not establish whether the
trigger was total transfer duration, an idle interval, or a transient network
condition. The failure path is under the artifact store's temporary pull
directory and does not publish an artifact record.

## Evidence limits

- Each package has one failed CI observation in this pass, on one self-hosted
  runner and one network route during the same short time window.
- The local ORAS control is a separate client but used the same host and route;
  its later HTTP/2 disconnect is corroborating stress evidence, not an
  independent registry-health sample.
- A later fresh pull with the downstream client did succeed, and a different
  route or warm cache may be faster. This report therefore does not claim a
  permanent GHCR outage or a universally failing OST pull.
- The actionable gap is narrower: a plausible transient slowdown or disconnect
  consumes the uncached CI cell because v0.21.0 exposes no retry/resume policy.
  The follow-up GPU CI rerun is part of this report's final disposition.

The complete-package control succeeds:

ost artifact import <complete-26.05-package-directory> --json
ost artifact verify `
  sha256:c69f605f5b2f6689badbb1ccb9e1fa4b0d65dd5aeaf22df5603b2e334f8103ea `

## Follow-up CI observation

The first downstream-client rerun pulled or restored both pinned package
artifacts, materialized both runtimes, and completed both CMake configure
steps. That retires the original pre-configure transport blocker for the rerun.
Both builds then exposed an independent downstream cache defect: the restored
LunarG SDK contained the required executables but not
`Include/vma/vk_mem_alloc.h`, which OpenUSD's public HgiVulkan wrapper includes.

hdMerlin now treats that header as part of its Vulkan SDK cache-completeness
check and uses a new cache key. OpenUSD remains sourced from the Animu-sphere
runtime package; VMA remains supplied by its declared external Vulkan SDK
dependency. This later failure does not indicate a bad OpenStrata artifact
digest or failed runtime materialization.

## v0.22.0 acceptance criteria

### Reliable large-layer transfer

- A throttled registry fixture takes more than 120 seconds to send a valid blob
  and still completes with the default pull policy.
- Connect timeout, response-header timeout, body-idle timeout, and overall
  timeout are distinct. CLI or documented environment/config controls can
  override the bounded values without disabling digest verification.
- The default body policy does not interpret a slow but continuously advancing
  archive as a response timeout.

### Digest-safe retry and resume

- A forced disconnect after a substantial prefix retries with bounded
  exponential backoff and resumes from verified local length when the registry
  supports byte ranges.
- `Content-Range`, total size, descriptor digest, and final file digest are
  checked before the blob becomes importable.
- If a registry ignores or rejects a range request, OST safely restarts the
  layer instead of appending duplicate bytes.
- Redirect and authorization rules remain fail-closed: credentials are not
  replayed to a different origin during initial or resumed requests.
- Interrupted partials are keyed by OCI layer digest, cannot satisfy
  `artifact show`, and are scavenged by an explicit bounded policy rather than
  being confused with complete artifact objects.
- Tests cover disconnect, timeout, ignored range, changed ETag/content,
  corrupted partial bytes, retry exhaustion, and a successful resumed import.

### Actionable CI evidence

- JSON reports the OCI manifest digest, layer title and digest, expected and
  received bytes, attempt count, resume offset, elapsed time, last-progress
  age, and the specific timeout/retry decision.
- Human output names the failing layer and gives a direct next action.
- The generated GitHub Actions runtime bootstrap uses this path, keys cache by
  the OpenStrata artifact digest, and never caches an unverified partial.
